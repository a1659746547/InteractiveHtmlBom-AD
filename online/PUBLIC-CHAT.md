# 公共聊天室（本地版）

2026-10-19，已完成本地验证，未同步服务器。

## 2026-10-20 界面整理

主界面以消息为主，展示开关移到独立设置页。入口和面板标题统一为“聊天室”，仅在解析后的查看界面显示；首页、正在重新解析或解析失败时隐藏并收起。回到导入页会撤回实时焊接信息并暂停聊天刷新，已发布的消息保留。

顶部自己的头像固定在最前，其他在线用户按最近文字发言排序；从未发言的用户保持进入顺序，进度、头像更换及完成播报不触发重排。只有主动公开进度的用户才显示外圈进度及百分比，不公开时不显示成 0%。点击头像展开其已公开的进度、板名、位号、型号，再点同一头像或关闭按钮收起；用户退出后移除头像与对应详情。头像较多时横向滚动，键盘可逐个聚焦进入。

消息旁显示对应昵称头像，自己与他人的气泡分别靠右／左，不重复附带进度；完成记录保留轻量提示行与临时滚动播报。头像不需要上传图片或外部请求，也不表示已认证身份。聊天、同步和公开范围规则保持不变。

## 使用

导入文件进入查看界面后，右下角“聊天室”打开可收起的聊天面板。昵称输入框左边可选 20 个内置 SVG 头像；加入后可在展示设置的“更换头像”中调整。本机记住选择，头像不需要上传或外部请求。更换后在线头像和本次会话已发消息的头像一起更新，消息数据库保存头像编号；旧消息没有编号时保留昵称首字头像。没有跨设备账号关联。

填写昵称后进入公共聊天室，网站用户可发送文字消息，Enter 发送、Shift+Enter 换行；中文输入法选词时不会误发送。匿名昵称由使用者自行填写，不是经过认证的身份。

右上角“展示设置”中可独立设置：

- 焊接进度：一个开关，开启显示整板装配百分比，关闭不展示进度。
- 板子名称：勾选后展示当前 PCB 标题。
- 位号与型号：一个开关，同时展示／隐藏当前选中元件的位号与 BOM 数值／型号，例如 R2 与 ESP32-S3；分组位号最多前三个及省略号，不猜测缺失型号。
- 焊完时播报型号：默认关闭。开启后，后续新勾选为已装配的元件会发布一条完成动态，聊天框顶部滚动展示约 40 秒，并保留聊天消息。只播报元件型号，不附带位号或板名；相同板子中的同一个元件不因撤销再勾选而重复播报。分组同时完成时合并相同型号，多种型号在一次更新中合并发送。

默认全部隐藏、完成播报关闭；板名、位号与型号组合、进度三个展示开关可独立选择；位号和型号随同一开关同步。更换 PCB 后这些选项全部重置。开启播报时不会补发此前已经完成的元件；没有型号的条目不生成空动态。消息重试使用事件标识去重；系统启用减少动态效果时，完成提示静态展示。选择范围后，下方会预览实际展示内容。进度按整板 BOM 的 Placed 勾选计算，不受搜索或当前正反面筛选影响；仅供用户主动展示自己记录的状态，不表示后台验证了实际焊接质量。

约 2 秒刷新消息与在场用户，装配状态变化在下一次同步后更新。聊天室收起后继续同步已选择展示的信息。退出聊天立即移除在场信息；缺少心跳约 60 秒后不再列为在线，并清除实时公开详情；正常关闭网页会尽快退出。在线状态与会话分开处理，无活动会话在内存保留最多 2 小时，活跃心跳续期，不会因后台标签短暂停顿就删除登录状态。更换 PCB 自动恢复全部隐藏；板名在其开关开启后发送，位号和型号只在合并开关明确开启后发送，不发送完整 PCB、图纸或未选择公开的字段。型号来源是 BOM 的数值／型号列。

进度、板名、位号及当前型号以在场状态展示，不写入消息历史；头像进度和展开的用户详情会随展示开关更新。主动发出的文字与启用播报后生成的完成动态属于公开消息，修改展示范围不会删除已发布消息。聊天室内的展示状态与会话令牌仅留在内存，昵称保存在本机浏览器；原有装配进度的浏览器保存逻辑保持不变。本页已主动加入过的会话，网络恢复、标签页唤醒或服务重启后会自动尝试恢复；重连失败按 2／4／8 秒等递增至最多 30 秒的间隔重试。未发送文字保留，不自动补发文字或离线期间的完成播报，主动退出会取消重连。刷新页面仍需重新进入聊天室，令牌不写入本机存储。

## 本地预览

执行 `python start_local.py`，在同一个地址打开两个独立浏览器会话，各自导入文件进入查看界面，即可打开聊天室。真实运行数据写入 `.local-data/chat/chat.sqlite3`，分享数据仍在 `.local-data/shares/`。可通过 `PCB_LOCAL_DATA_DIR` 环境变量将测试运行数据放到独立目录；该目录及缓存文件不得加入交付包。

本地聊天室只连接本机，没有向生产服务器发送消息或用户 PCB。独立导出 HTML 不内嵌聊天室。

## 维护与上线

- `public-chat.js`、`public-chat.css`、`chat-avatars.js`：前端及 20 个内置头像编辑源，已内嵌到首页。修改后运行 `python embed_public_chat.py` 更新首页与清单。
- `chat_server.py`：Python 标准库后端，SQLite 消息历史，无额外 pip 依赖。
- `start_local.py`：本地分享与聊天 API 的统一入口。
- `pcb-chat.service`：生产独立服务模板，监听 `127.0.0.1:8770`，不占用原分享 8767、统计 8768、反馈 8769。
- `chat-nginx.conf`：仅 `/api/chat/` 的反向代理片段，未来经确认部署时并入现有 HTTPS 站点。

上线需要同时部署独立聊天后端、systemd 服务及这段 Nginx 路由，再发布首页；已有聊天后端也需更新并重启，以支持头像编号、profile 接口、发言顺序及独立会话有效期。数据库会自动增加可空的 avatar_id 列，旧消息保留，发布前仍需备份。不能只更新静态首页。部署时需为 www 用户配置 `/opt/pcb-chat` 代码目录、`/var/lib/pcb-chat` 状态目录，按实际域名设置 `CHAT_ORIGIN`，检查 Nginx 后再重载，不改动原统计、分享数据或 SMTP 配置。

每条消息最多 600 字，昵称最多 20 字；保留最近 7 天且最多 300 条消息，页面显示最近 20 条。最多 100 名在场用户，最多缓存 1000 个会话，满时优先回收最久未活动的离线会话；单会话每分钟最多 20 条、同来源每分钟最多 40 条消息，限制加入和进度更新频率。接口只接受本站 Origin 的 JSON 写入，并校验请求体大小、会话令牌和展示字段。消息、昵称及板名均以纯文本渲染，不支持 HTML、文件或图片上传；没有原始 IP 访问日志。

目前没有账号系统、私信、图片、管理员审核或消息撤回功能。这一版本提供公共文字交流和用户主动选择的实时焊接状态。
